# fruehling-corporate.de

Professionelle, minimalistische B2B-Website für Due Diligence und
Unternehmensanalyse im Mittelstand.

## Tech-Stack

- Next.js (App Router)
- TypeScript
- Tailwind CSS
- Deployment über Vercel

## Lokale Entwicklung

1. Abhängigkeiten installieren:

	```bash
	npm install
	```

2. Umgebungsvariablen setzen (siehe `.env.example`):

	```bash
	RESEND_API_KEY=...
	CONTACT_TO_EMAIL=...
	PLAYBOOK_FILE_PATH=/PLAYBOOK WIN - OEM Verhandlungen meistern.pdf
	SUPABASE_URL=https://your-project-ref.supabase.co
	SUPABASE_SERVICE_ROLE_KEY=...
	```

3. Dev-Server starten:

	```bash
	npm run dev
	```

4. Anwendung öffnen: <http://localhost:3000>

## Kontaktformular (Resend)

Das Formular auf `/contact` sendet E-Mails serverseitig über Resend
(`POST /api/contact`).

- Absender: `Fruehling Corporate <kontakt@mail.fruehling-corporate.de>`
- Empfänger: `CONTACT_TO_EMAIL` (Fallback: `cfruehling@live.de`)

Wichtig für Produktivbetrieb:

- Domain/Absender in Resend verifizieren (`mail.fruehling-corporate.de`)
- `RESEND_API_KEY` in Vercel-Projekt-Settings hinterlegen

## Leads in Supabase speichern

Sowohl das Kontaktformular (`POST /api/contact`) als auch das
Playbook-Formular (`POST /api/playbook-request`) speichern Anfragen in
Supabase in der Tabelle `inbound_leads`.

1. In Supabase SQL Editor ausfuehren:

	```sql
	create table if not exists public.inbound_leads (
	  id bigint generated by default as identity primary key,
	  source text not null check (source in ('contact', 'playbook_request')),
	  name text not null,
	  email text not null,
	  mobile_phone text,
	  company text,
	  message text,
	  privacy_accepted boolean not null default false,
	  created_at timestamptz not null default now()
	);

	alter table if exists public.inbound_leads
	add column if not exists mobile_phone text;
	```

2. In Supabase Project Settings die Werte fuer `SUPABASE_URL` und
   `SUPABASE_SERVICE_ROLE_KEY` kopieren.

3. Beide Werte als Environment Variables lokal und in Vercel setzen.

Hinweis: Ohne Supabase-Variablen laufen die Formulare weiterhin,
es wird dann nur kein Datensatz gespeichert.

## Spamschutz des Playbook-Formulars

Vor dem Deployment `supabase/playbook-rate-limit.sql` im Supabase SQL Editor
mit administrativen Rechten ausführen. `SUPABASE_URL` und
`SUPABASE_SERVICE_ROLE_KEY` müssen in der Produktionsumgebung gesetzt sein.
Die Funktion ist ausschließlich für `service_role` freigegeben.
Ohne funktionierende zentrale Begrenzung wird in Produktion kein Versand
zugelassen; die Seite zeigt dann einen Versandfehler an.

Die Route validiert alle Felder serverseitig, blockiert Links im Namensfeld,
prüft den vorhandenen Honeypot `companyWebsite` und begrenzt den Request-Body
auf 16 KiB. Erst danach werden maximal fünf gültige Anfragen je IP und zwei
je normalisierter E-Mail-Adresse innerhalb eines festen Stundenfensters
zugelassen. Auch abgewiesene Wiederholungen zählen innerhalb dieses Fensters.
Blockierte Anfragen speichern keinen Lead und versenden keine der beiden Mails.

Die IP wird ausschließlich aus dem von Vercel überschriebenen Header
`x-vercel-forwarded-for` gelesen. Außerhalb von Vercel oder ohne gültigen
Header gilt ein gemeinsamer IP-Bucket; bei anderem Hosting muss die vertrauenswürdige
Proxy-Quelle angepasst werden. Identitäten werden als HMAC-SHA256 gespeichert,
keine Klartext-IP oder E-Mail in der Limiter-Tabelle. Abgelaufene Buckets werden
bei nachfolgenden Anfragen gelöscht. Lokal ohne Supabase greift eine
prozesslokale Begrenzung, die nicht für Produktion verwendet wird.

Regressionstests ohne echten Mailversand:

```bash
node --test tests/playbook-spam.test.cjs
```
